多轮训练的关键技术

目标：理解 Agentic RL 和单轮 RL 在实现上真正不同的地方。这些点不处理好，训练会“看起来在跑，实际在跑偏”。本课先讲基本概念，再对信用分配、训推一致、上下文成本和指标诊断逐一展开。

2. 信用分配：好步骤会不会被一起罚

一条 20 回合的轨迹最终失败了，问题可能只出在第 3 回合查错了订单。轨迹级奖励会把 20 个回合“一起罚”，好的步骤也被罚了。三种思路：

  • 靠样本量平均：GRPO 默认做法。轨迹够多时，好步骤在成功轨迹里出现得更频繁，统计上会被区分出来。简单，但样本效率低。
  • 回合级奖励：对能评分的中间步骤单独打分。SageMaker AI 多轮 RL 支持通过 UpdateReward 接口上报逐回合奖励。
  • 以回合为转移单位的算法：如 Agent-R1 等工作把每次交互作为 RL 的基本转移，做回合级优势估计。

2.1 用数字算一遍

同一个任务采样 4 条轨迹，每条 4 个回合。只有 4 个回合都做对，任务才算成功（结果奖励 1，否则 0）。

轨迹级（GRPO 默认）：每条轨迹的优势 Ai = (ri − 组均值) / 组标准差，这条轨迹里的每个回合都拿同一个 A。如果组里只有 1 条成功，那 3 条失败轨迹里做对的回合也全部拿到负优势。

回合级（过程奖励 + 剩余回报）：每个回合有自己的过程奖励 pt（做对 +0.25、做错 −0.25，总和有界在 [−1, 1] 内），回合 t 的回报是“从这一回合到结束的所有奖励之和”：

Gi,t = Σk≥t pi,k + ri               # 剩余回报（reward-to-go），这里不打折扣，γ = 1
Ai,t = (Gi,t − 同一回合位置上 4 条轨迹的均值) / 标准差

这样，一个回合的优势主要取决于它本身和之后发生了什么，前面的错误不再直接算到它头上；做错的回合则会因为自己的负过程奖励被单独区分出来。不过它并不能完全消除误罚，见 2.3。

2.2 动手：点格子切换某个回合做对还是做错

默认情况下，轨迹级模式里 3 条失败轨迹中有 7 个做对的回合被判为负优势（黄框）。切到回合级后降到 5 个，并且做错的回合优势明显更低，好坏步骤被拉开了。再试试把轨迹 1 也改成失败：组内没有成功轨迹，轨迹级的优势全为 0，模型学不到任何东西；回合级仍然能靠过程奖励区分好坏步骤。这就是第 04 课“结果主导 + 有界塑形”在多轮场景下的样子。

2.3 为什么回合级还剩 5 个

剩下的 5 个分两类，都来自“在同一回合位置上跨轨迹比较”这个基线：

  • 好步骤后面跟着坏步骤（轨迹 4 回合 1；轨迹 2 回合 1、2）：剩余回报把之后的错误也算了进来。这正是剩余回报的设计意图，一步的价值包括它之后的结果，但它确实会连累这一步本身。
  • 错误已经发生、之后的好步骤（轨迹 2、3 的回合 4）：任务在第 2 或第 3 回合就已经注定失败，回合 4 做得再对也救不回来。可它的比较对象是轨迹 1 的回合 4，那条轨迹带着成功的 +1，所以它显得差。

问题在于基线只看“第几回合”，不看“当前处境”。要按处境比较，需要依赖状态的基线：

  • 价值网络（critic）：PPO 的做法，估计“从这个状态出发平均能拿多少”。代价是多训一个模型，长轨迹上不好训。
  • 从同一状态分叉采样：在某个中间回合复制环境快照，从这里重新采样几条后续，组内比较的就是同一处境下的不同选择。需要环境支持快照复位（AgentCore Runtime 的会话隔离 + 可复位环境），采样成本也更高。2025–26 年不少工作在探索这种树状或分段分组的做法。

2.4 回合级奖励的代价

  • 需要能给中间步骤打分。“查订单前先核对用户身份”能写规则判定，“这一步思考是否合理”通常不能。判不准的回合奖励比不给更糟。
  • 更容易被刷分。模型可能学会多做“容易得分”的步骤。过程奖励的总和必须有界，并且小于结果档位差（第 04 课第 3 节）。
  • 评审成本按回合数增加。每条轨迹 20 个回合，就是 20 次评分。

实践建议：先用轨迹级加足够大的组跑通；遇到长任务学不动、组内经常全失败时，再给几个关键步骤（确认、核对、写操作）加规则判定的回合奖励。

3. 训推一致：重新分词为什么会出问题

RL 的梯度里有一个关键量，重要性比率 ρ = πθ(token | 上下文) / πold(token | 上下文)（第 06 课），分母是采样时模型给这个 token 的概率。训练端必须在完全相同的 token 序列上重新计算概率，比率才有意义。在多轮智能体里，有三种常见的偏差：

① 重新分词不一致

采样时模型逐个生成 get、_order、(、88、)。智能体框架把文本存成消息，下一轮再套模板、重新分词，可能得到 get_、order(、88)。文本一样，token 不一样，训练端算的是一串模型从没生成过的 token 的概率。

② 模板改写了历史

很多 chat template 会在后续轮次删掉之前回合的思考内容，或者改写工具调用的格式。采样第 5 回合时模型看到的上下文，和训练时拼出来的上下文不一样，ρ 的分母和分子用的不是同一个条件。

③ 数值精度不同

推理引擎（vLLM、SGLang）和训练引擎用不同的算子和精度，同一个 token 的 logprob 会有小偏差。偏差不大，但长序列上会累积，第 06 课提到的截断重要性采样就是对策之一。

正确做法：在网关层记录采样时的原始 token id 和 logprob，训练直接用这串 token，不再从文本重建。AgentCore RL Toolkit 的 rollout 网关就是这么做的；多轮场景里，它还会把同一会话的多次模型调用拼成一条带 loss mask 的轨迹。

怎么检测：在第一个训练步、参数还没更新时，πθ 就等于 πold，所以 ρ 应该处处等于 1。记录这一步所有生成 token 的 |log ρ| 均值和最大值：只有数值精度带来的微小偏差是正常的；如果明显偏离 0，或者某些位置特别大（常见于工具调用边界、思考块边界），就是 ① 或 ② 在作怪。这一检查成本很低，应该作为每个新智能体接入训练时的第一项检查。

4. 上下文管理：多轮任务的成本为什么涨得这么快

每次调用模型都要重新读一遍全部历史。设系统提示加任务描述有 S 个 token，每个回合新增模型输出 g 个 token、工具返回 o 个 token，跑 T 个回合，总的 prefill token 数大约是：

prefill 总量 ≈ T·S + (g + o) · T(T − 1) / 2

第二项随回合数平方增长。AWS 的 Wordle 实验中 prefill 是生成 token 的 3 倍多；对工具返回很长的任务（网页、日志、代码文件），这个比例会大得多。托管多轮 RL 按 prefill、生成、训练三类 token 计费，所以上下文长度直接决定成本。

截断也要训推一致：训练时怎么截断，上线时就必须怎么截断，否则模型在训练里学会依赖“摘要后的旧工具输出”，上线却看到完整内容，行为会变。截断规则应该写在智能体代码里，训练和部署共用同一份（第 10 课“训练的智能体就是部署的智能体”）。推理引擎的前缀缓存能减少重复计算，但按 token 计费的托管服务通常仍按完整 prefill 计费，以定价页为准。

5. 其他必须处理的技术点

冷启动

如果基础模型连工具调用格式都做不对，奖励全是 0，GRPO 没有梯度。Bedrock 文档建议：基线接近 0% 先做 SFT；高于 95% 则 RL 收益有限。常用做法是让前沿模型（例如 Bedrock 上的 Claude）跑出成功轨迹，用来做蒸馏 SFT，再上 RL。

格式漂移

学习率过高时，模型可能把工具调用写成纯文本，所有 rollout 拿同样的最低分，梯度消失。这是 SageMaker 博客记录的真实踩坑。对策：降低学习率；从纯文本中恢复工具调用并给小幅格式惩罚；监控“有效工具调用率”。

环境隔离与可复位

每条 rollout 要有独立的文件系统和状态，且能恢复到初始快照。上千条并发轨迹共享一个数据库，会互相污染。AgentCore Runtime 为每个会话分配独立 microVM，会话结束即销毁，适合承担这一层。

评测设置要和服务一致

训练任务的验证通常用 temperature 0，但上线可能用 1.0。AWS 的 Wordle 实验中，训练曲线显示最终 37%，按服务设置评测是 84%。永远按你实际上线的解码参数评测。

6. 训练时要盯的指标

训练奖励均值稳步上升后趋于平台剧烈震荡或突然跌落
组内奖励方差保持非零趋于 0：任务太简单或太难，没有学习信号

6.1 诊断顺序：出了问题先查哪里

指标异常时，按“数据是怎么来的”从上游往下游查：先确认 rollout 本身是健康的，再确认奖励算对了，然后才怀疑算法和超参数。顺序反过来，常常调了一周学习率，最后发现是奖励函数解析失败。

    如果不屏蔽工具返回的 token，会发生什么？
    正确答案 A。工具返回是环境产生的，不是模型的动作，不应该进入策略梯度。
    第一个训练步、参数还没更新时，生成 token 的 |log ρ| 均值明显大于 0，最可能的原因是？
    正确答案 B。参数没更新时 πθ = πold，ρ 应该等于 1。偏离只能来自“算的不是同一串 token、同一个上下文”，或者数值精度。学习率和奖励都还没起作用。
    一个 20 回合的任务，组内 8 条轨迹经常全部失败。最该先做什么？
    正确答案 C。全部失败时轨迹级优势全为 0，没有梯度。回合级过程奖励能在失败轨迹之间产生差异；SFT 和课程式拆分能把成功率拉进可学习区间。
