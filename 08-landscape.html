4. 各家公开报告的结果

下表只收录有一手来源的数字。“前 → 后”都是来源自己报告的，我们没有复现。每一行的“注意”列写的是读这个数字时要问的问题，与第 04 课第 4.6 到 4.8 节讲的评测诚实性是同一套逻辑。

4.1 基准污染和评测偏差：几个已经公开的例子

  • SWE-bench Verified 已被提出方之一停用。OpenAI 发文说明不再评测 SWE-bench Verified（二手报道的发布日期为 2026-02）：他们审计了模型常失败的 27.6% 题目，发现其中至少 59.4% 的测试会拒绝功能正确的提交；前沿模型还能复现部分题目的参考修复。之后 OpenAI 又发文称其推荐的替代品 SWE-Bench Pro 也有设计问题。所以表中所有 SWE-bench Verified 数字只能作为相对参考。
  • 环境本身可能有捷径。SWE-Gym 的 README 提醒，环境里存在与 SWE-bench issue #465 类似的 git 捷径（智能体能从 git 历史里看到答案），使用前要先跑清理脚本。RL 会主动找到这种捷径，比提示词评测更容易被它污染。
  • 训练任务和测试来自同一个环境。AgentCore RL Toolkit 的 τ²-Bench 结果用的训练任务，是从同一套工具、数据库和政策文档合成的。这证明了“在这个环境里能学会”，不能说明换一个客服系统也一样好。博客对每道题跑 5 次，报告了“总是成功 / 时好时坏 / 总是失败”的比例，这一点比只给平均分可信。
  • 评审模型和工具在变。Kimi-Researcher 的 HLE 分数用 o3-mini 判分，并说明搜索工具的波动会影响结果、给出了评测日期。换评审或换日期，数字都可能变。
  • 数据集是公开的。MigrationBench 的仓库都是 GitHub 上 MIT / Apache-2.0 的公开项目，GSM8K、AIME 2024 也早已公开，底座模型可能在预训练时见过。“前 → 后”的差值比绝对分更有参考价值，因为前后用的是同一个底座。

7. 怎么读厂商的宣称

拿到一个“RL 后从 X% 提升到 Y%”的数字，逐项检查。勾选来源里能找到答案的项目。

以第 4 节的 τ²-Bench Telecom 38% → 96% 为例：同一底座前后对比、114 道题每题 5 次、拆出 SFT（0.90）和 RL（0.96）各自的贡献，这几项都有；但训练任务和测试同属一个环境，也没有在另一个客服系统上测。所以它支持的结论是“用环境合成任务，能把小模型在这个环境里的稳定性练上去”，而不是“96% 的通用客服能力”。

8. 格局小结

  • 闭源前沿实验室把 Agentic RL 用在旗舰产品上（深度研究、编码智能体），方法细节很少公开。OpenAI 的自助微调平台（含 RFT）正在关停，Agent Builder 和 Evals 计划 2026-11-30 关停。
  • 中国开源模型团队贡献了大部分公开的算法和框架：GRPO（DeepSeek）、GSPO（Qwen）、DAPO（字节 Seed）、CISPO（MiniMax），以及 verl、slime、AReaL、ROLL。
  • 开源框架已经从“能跑 GRPO”走到“能接任何智能体 harness”：rLLM、Agent Lightning、AgentCore RL Toolkit 都用网关捕获 token，让智能体代码在评测和训练中保持不变。训练系统则在比拼异步、MoE 和超大模型（SkyRL 首日支持 501B 的 MoE；verl README 收录了 Mind Lab 在 64 张 H800 上对万亿参数模型做 GRPO LoRA 的案例）。
  • 云厂商在做托管化。AWS 目前形成了 Bedrock RFT（单轮）→ SageMaker AI 多轮 RL（托管多轮）→ SageMaker 训练会话 API（自写算法、不管 GPU）→ HyperPod / EKS 自建的梯度，AgentCore Runtime 负责 rollout。Tinker 和 Prime Intellect 是 AWS 之外的两种托管形态：前者按 token 计费，后者按 GPU 小时计费。
  • 环境是新的稀缺资源：Prime Intellect 的 Hub 已有 2,500+ 个环境；从环境本身合成可验证任务（AgentCore RL Toolkit、DeepSeek-V3.2、Kimi K2）是 2026 年的热点。同时基准在快速失效，SWE-bench Verified 已被停用，评测要用自己的隐藏集。

9. 小测验

某方案报告：用从客服环境自动合成的任务训练后，小模型在该环境的测试集上从 38% 提升到 96%，超过前沿模型。最重要的追问是？
正确答案 B。同环境内的提升是真实的（来源还给了每题 5 次的一致性分析），但不能外推为跨环境泛化。114 题不算多，可以算置信区间，但不是“没有意义”。
客户要训练一个多轮客服智能体，数据必须留在自己的 AWS 账户，没有 GPU 团队，托管模型加 LoRA 就够。首选是？
正确答案 C。A 的数据在 OpenAI 平台，且自助微调平台正在关停；B 的训练在 Thinking Machines 的基础设施上。C 是 serverless、按 token 计费，智能体和数据都在客户账户内，也是第 09 课向导对“多轮 + 托管”的推荐。
一个开源项目报告：纯 RL 让某 MoE 模型在 SWE-bench Verified 上从 47.8% 提升到 61.6%。下面哪个问题最该先问？
正确答案 B。框架和算力决定成本，不决定数字是否可信。同一底座的前后差值比绝对分可靠，但仍要确认评测设置一致、有多次运行，并把基准本身的缺陷算进去。最终还是要在客户自己的隐藏集上验证（第 04 课第 4.8 节）。
