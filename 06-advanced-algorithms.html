算法家族：从 PPO 到 GRPO 的各种变体

目标：看懂主流算法论文在改什么，能和算法团队讨论该选哪个。

1. 先读懂 GRPO 目标函数

L(θ) = − E[ 1/G Σ_i  1/|o_i| Σ_t  min( ρ_{i,t}·A_i ,  clip(ρ_{i,t}, 1−ε, 1+ε)·A_i ) ]  +  β·KL(π_θ ‖ π_ref)

ρ_{i,t} = π_θ(o_{i,t} | ctx) / π_old(o_{i,t} | ctx)   # 重要性比率：当前策略 vs 采样时的策略
A_i     = (r_i − mean(r)) / std(r)                    # 组内相对优势，同一轨迹的所有生成 token 共享
clip    限制单步更新幅度，防止一次走太远                 # 来自 PPO
Σ_t     只对 mask = 1 的 token 求和                    # 工具返回不参与（见第 05 课）
KL      防止偏离参考模型太远；很多 Agentic 实践把 β 设得很小或为 0

2. 动手：看 clip 怎么限制更新

拖动 εhigh，模拟 DAPO 的 clip-higher
当 A>0 且 ρ 已经超过 1+εhigh，这个 token 的梯度被截断为 0，不再继续提高它的概率。对低概率的“探索性” token 来说，ρ 很容易超过上限，导致模型越来越保守（熵塌缩）。DAPO 把 εhigh 调大（clip-higher），就是给这些 token 留出上涨空间。

3. 算法速查

算法来源核心改动在智能体场景的意义
PPOOpenAI 2017，RLHF 经典clip 比率 + 价值网络 + GAE理论上能做逐步信用分配，但价值网络在长轨迹上难训练，且显存翻倍
GRPODeepSeekMath / DeepSeek-R1组内相对优势，去掉价值网络当前默认选择；Bedrock RFT、SageMaker AI 多轮 RL 采用
RLOO学界留一法基线：用组内其他样本的均值做基线无偏、简单，常作对照
REINFORCE++OpenRLHF全局批次归一化优势减少小组内归一化的方差
DAPO字节 Seedclip-higher、动态采样、token 级损失、超长惩罚长轨迹下防熵塌缩；丢弃零梯度组
Dr.GRPOSea AI Lab 等去掉长度归一化和标准差归一化避免“越长的错误回答被罚得越轻”的偏差
GSPO阿里 Qwen用序列级重要性比率和序列级 clipMoE 模型上更稳定
CISPOMiniMax-M1裁剪重要性采样权重本身，而不是丢掉 token 的梯度保留关键“反思”token 的梯度
回合级方法Agent-R1 等 2025–26 工作以一次交互为 RL 转移单位，做回合级优势长程任务的信用分配

4. 怎么选

  • 用托管服务：算法已经定了（GRPO 及其调参），你能调的是 group size、学习率、最大 token 数、奖励函数。
  • 自建且任务较短：GRPO 或 Dr.GRPO 起步，加上 DAPO 的动态采样。
  • MoE 底座：优先尝试 GSPO。
  • 长程任务、回合多：考虑回合级奖励或回合级优势，配合异步 rollout。
  • 不管选哪个：先确认奖励和环境没有问题。经验上，算法差异带来的提升通常小于奖励和数据质量带来的提升。

5. 离策略修正

为了提高 GPU 利用率，异步系统会用落后几个版本的权重继续采样（第 07 课）。这时 πold 和 πθ 差得更远，ρ 偏离 1 更多，需要：限制最大落后版本数；用重要性采样修正；对 ρ 做截断。推理引擎和训练引擎的数值精度不同（例如 bf16 与 fp32）也会让 ρ 偏离 1，这是 2025–26 年社区关注的“训推不一致”问题之一。
