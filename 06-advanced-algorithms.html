算法家族：从 PPO 到 GRPO 的各种变体

目标：看懂主流算法论文在改什么，能和算法团队讨论该选哪个。本课先读懂 GRPO 的目标函数，再用具体数字逐项拆开：优势怎么算、clip 什么时候让梯度变 0、损失怎么聚合、要不要除以标准差、比率按 token 还是按序列算、KL 什么时候需要、异步采样怎么修正。每一项都对应一篇论文里的一个改动。

1. 先读懂 GRPO 目标函数

L(θ) = − E[ 1/G Σ_i  1/|o_i| Σ_t  min( ρ_{i,t}·A_i ,  clip(ρ_{i,t}, 1−ε, 1+ε)·A_i ) ]  +  β·KL(π_θ ‖ π_ref)

ρ_{i,t} = π_θ(o_{i,t} | ctx) / π_old(o_{i,t} | ctx)   # 重要性比率：当前策略 vs 采样时的策略
A_i     = (r_i − mean(r)) / std(r)                    # 组内相对优势，同一轨迹的所有生成 token 共享
clip    限制单步更新幅度，防止一次走太远                 # 来自 PPO
Σ_t     只对 mask = 1 的 token 求和                    # 工具返回不参与（见第 05 课）
KL      防止偏离参考模型太远；很多 Agentic 实践把 β 设得很小或为 0

2. 从 PPO 到 GRPO：用同一组 4 个样本算一遍

同一道题采样 4 条回答，奖励是 0 或 1。PPO 和 GRPO 的区别只在基线：优势 = 奖励 − 基线，基线回答“这道题平均能拿多少分”。

  • PPO：用一个价值网络（critic）V(s) 预测基线。只有结尾有奖励、并取 γ = λ = 1 时，GAE 化简为 At = r − V(st)，下表用的是第一个 token 处的 V(s0)。
  • RLOO：基线是其他样本的平均奖励。
  • GRPO：基线是包括自己在内的组均值，再除以组内标准差。DeepSeekMath 提出时的理由是：价值网络通常和策略模型一样大，显存和计算开销大；而且奖励只在最后一个 token 给出，很难把每个 token 的价值训准。
点击切换奖励：
默认情况下 4 条里只有 1 条成功，组均值 0.25。价值网络如果预测 0.60（例如它主要在更容易的题上训练过），PPO 给 3 条失败回答的优势都是 −0.60，四个优势加起来是 −1.40：这一步整体在压低所有回答的概率。GRPO 的组均值基线保证一组的优势之和为 0。把 V 拖到 0.25，PPO 就和“减组均值、不除 std”那一行完全一样。再把 4 条都改成 0：组内方法的优势全为 0，而 PPO 只要 V 不等于 0 就仍有信号，这是价值网络的好处之一。

标准差这里用总体标准差（除以 G）。有的实现用样本标准差（除以 G − 1），这一组会得到 1.50 / −0.50，而不是 1.73 / −0.58。

2.1 显存：去掉价值网络省了多少

按 ZeRO 论文的估算，混合精度 Adam 训练每个参数大约要 16 字节（bf16 权重 2 + bf16 梯度 2 + fp32 主权重、动量、方差共 12）。冻结、只做前向的模型按 bf16 每参数 2 字节。PPO 要训练两个同样大的模型（策略 + 价值网络），GRPO 只训练一个。

这是粗估，只算权重、梯度和优化器状态，不含激活、KV cache 和 rollout 推理引擎，ZeRO 分片也只是把这些字节分到多张卡上，总量不变。

3. clip 机制：什么时候梯度变成 0

PPO 的 clip 目标是 min(ρ·A, clip(ρ, 1−εlow, 1+εhigh)·A)。min 取到被截断的那一项时，目标对 ρ 是常数，梯度为 0；取到未截断的 ρ·A 时，梯度正常。

预设：
目标值随 ρ 的变化（实线：clip 目标；虚线：未截断的 ρ·A；阴影：梯度为 0 的区间）

clip 只在“朝优势方向走过头”时生效，两个方向不对称：

梯度为 0 的区间其余区间
A > 0（想提高概率）ρ > 1 + εhigh：已经提高够了，不再继续提高ρ 很小时（例如 0.6）梯度照常，因为把概率拉回来正是想要的方向
A < 0（想降低概率）ρ < 1 − εlow：已经降够了ρ 很大时梯度照常，而且权重 ρ 没有上限。CISPO 和截断重要性采样都会处理这种大比率（第 6、8 节）

DAPO 论文用的正是 0.01 和 0.9 这组例子：高概率的“利用型” token 几乎不受上限约束，低概率的“探索型” token 一步只能涨一点点。论文还观察到，被上限截断的 token 平均概率低于 0.2，并在朴素 GRPO 上看到熵快速下降（熵塌缩）。对策是把上下界拆开：εlow 保持 0.2，εhigh 提高到 0.28。εlow 不跟着调大，是因为调大会让低概率 token 被一路压到 0，采样空间塌缩。

在 DAPO 的消融表中（Qwen2.5-32B 底座，AIME 2024 avg@32），朴素 GRPO 为 30 分；依次加入超长过滤、clip-higher、软超长惩罚、token 级损失、动态采样后到 50 分，其中加入 clip-higher 这一步从 36 到 38。

4. 损失怎么聚合：一条回答有多少话语权

同一组里回答长短不一。把每个 token 的损失加成一个标量时，除以什么，决定了每个 token 的权重。在 ρ = 1 附近，每个 token 的梯度系数就是下表里的“每 token 权重”：

GRPO 样本级平均   (1/G) · Σ_i (1/|o_i|) Σ_t (...)      每 token 权重 = A_i / (G · |o_i|)
DAPO token 级平均  (1/Σ_i|o_i|) · Σ_i Σ_t (...)         每 token 权重 = A_i / Σ_j|o_j|
Dr.GRPO 常数归一化 (1/G) · Σ_i (1/L_max) Σ_t (...)      每 token 权重 = A_i / (G · L_max)
默认情况：一条 100 token 的正确回答（A = +1）和一条 400 token 的错误回答（A = −1）。 GRPO 给两条回答各 0.5 的总权重，摊到每个 token 上，长的错误回答每个 token 只被罚 0.00125，是短回答的 1/4。Dr.GRPO 论文指出这就是长度偏差：正确回答里越短的更新越大，错误回答里越长的被罚越轻，模型因此倾向于把错误回答写长。 DAPO 和 Dr.GRPO 让每个 token 权重相同，长回答的总权重随长度增加（这里 −0.8 对 +0.2）。两者的区别在分母：DAPO 除以这批数据实际的 token 总数，一个 token 的权重会随同批其他回答的长度变化；Dr.GRPO 除以一个固定常数，跨批次也一致，只影响梯度的整体大小。

token 级平均也有代价：错误回答往往更长，负梯度在总量上占优。MiniMax-M1 在把生成长度从 40K 逐步扩到 80K 时就遇到了这个问题：负样本长度增长得比正样本快，后半段序列积累了过大的负梯度，最后改成样本级损失与 token 级归一化结合的方式来缓解。在 verl 中，这三种方式分别对应 loss_agg_mode 的 seq-mean-token-mean（GRPO）、token-mean（DAPO）和 seq-mean-token-sum-norm（Dr.GRPO）。

5. 优势要不要除以标准差

GRPO 的 A = (r − 组均值) / 组标准差。Dr.GRPO 认为除以 std 会带来题目难度偏差：std 小的题（几乎全对或几乎全错）被放大了权重。看一组 G 条回答、其中 k 条正确的二值奖励：

一组的总梯度量 Σ|A|，相对“一半对一半错”的组（实线：除以 std；虚线：不除）
默认是一道简单题：8 条里 7 条对。除以 std 时，唯一那条错误回答的优势是 −2.65，不除时是 −0.875。看整组：二值奖励下 Σ|A| 除以 std 时等于 2G·√(p(1−p))，不除时等于 2G·p(1−p)，p = k/G。以“4 对 4 错”的组为 1，这道简单题的相对权重除以 std 时是 0.66，不除时是 0.44。也就是说，除以 std 让太简单和太难的题在更新里占了更大比重。全对或全错时两种方式的优势都是 0，DAPO 的动态采样会直接过滤掉这类组，继续采样直到批次填满。

是否去掉 std 并没有统一结论：除以 std 让不同题的优势落在相近的尺度上，不除则保留了“这道题还有多少可学”的信息。按自己的任务做对照实验，并同时看第 4 节的聚合方式，两者会叠加。

6. 比率按 token 算还是按序列算：GSPO 与 CISPO

GRPO 给每个 token 一个比率 ρt，逐个 clip。两种改法：

  • GSPO（Qwen）：奖励是给整条序列的，比率也按序列算。用长度归一化的序列比率 s = (π_θ(y)/π_old(y))^(1/|y|) = exp(mean_t log ρ_t)，即各 token 比率的几何平均，再对整条序列 clip。不做长度归一化的话，几个 token 的变化就能让序列比率剧烈波动，不同长度的回答也需要不同的 clip 范围。因为 s 通常非常接近 1，GSPO 的 clip 范围比 GRPO 小几个数量级：论文里 GSPO 左右分别用 3e-4 和 4e-4，对照的 GRPO 用 0.2 和 0.27。
  • CISPO（MiniMax-M1）：不丢 token 的梯度，而是裁剪重要性权重本身，并对它停梯度：sg(clip(ρ_t, 1−εlow, 1+εhigh)) · A · log π_θ(o_t)。在 clip 范围内，它的梯度和 PPO 相同；超出范围时，PPO 的梯度变 0，CISPO 仍保留这个 token 的梯度，只是权重封顶。论文实验中没有设下界（εlow 取得很大），只调 εhigh。

默认第 3 个 token 的 ρ = 1.60，像是一个原本概率很低、更新后被大幅提高的“反思”token（MiniMax 论文举的例子是 However、Recheck、Wait 这类词）。A = +1 时： token 级 clip（0.2 / 0.28）把它的梯度置 0，其余 4 个照常； GSPO 的序列比率 s = 1.098，远超 1 + 4e-4，整条序列都不参与这次更新。GSPO 论文确实报告了它被 clip 的 token 比例比 GRPO 高约两个数量级，但训练效率仍然更高；放宽范围后可以看到 GSPO 给 5 个 token 相同的权重； CISPO 保留全部 5 个 token 的梯度，第 3 个的重要性权重被封顶在 1.28，表中系数是 1.28/5 = 0.256（这里的 εhigh = 0.28 只是示例值，论文正文没有给出具体取值）。 切到 A = −1：token 级 clip 对 ρ = 1.60 不再截断，权重是 −1.60/5 = −0.32，没有上限；CISPO 仍封顶在 −1.28/5。

两者解决的问题不同。GSPO 针对的是 token 级比率噪声大，在 MoE 模型上尤其明显：论文观察到 Qwen3-30B-A3B 每次梯度更新后，同一条样本约有 10% 的激活专家发生变化，token 级比率随之剧烈波动，GRPO 需要 Routing Replay 才能正常收敛，GSPO 不需要。CISPO 针对的是低概率关键 token 在第一次更新后就被 clip 掉：MiniMax 的设置里每批数据做 16 轮 off-policy 更新，DAPO 的 clip-higher 不够用；在 Qwen2.5-32B 的对照实验中，CISPO 用一半训练步数达到了 DAPO 的 AIME 2024 成绩。GSPO 还有一个 token 级变体 GSPO-token，允许多轮场景里给不同 token 不同优势。

7. KL 项：什么时候需要 β > 0

KL 项把策略拉向参考模型 πref。它在 RLHF 里很重要：奖励模型是在参考模型的输出分布上训练的，策略跑远了，奖励模型就不准，容易被钻空子。奖励来自规则验证器时，这个担心小得多。DAPO、Dr.GRPO（假设 β = 0）和 CISPO 都去掉了 KL 项；Dr.GRPO 指出，去掉后还省掉了参考模型的显存和前向计算。作为对照，DeepSeekMath 的 GRPO 用的是 β = 0.04，并且把 KL 直接加在损失里，而不是像 PPO 那样加进每个 token 的奖励。

KL 只能用采样到的 token 估计。记 r = πref(ot) / πθ(ot)，常见的两个估计量（Schulman 的 k1 / k3 记法）：

k1 = −log r              无偏，但单个样本可能为负，方差大
k3 = (r − 1) − log r     无偏，且恒 ≥ 0，方差通常更小；DeepSeekMath 的 GRPO 用的就是它

试试 πθ = 0.30、πref = 0.45：k1 = −0.405，是负的；k3 = 0.095。还要注意一个实现细节：k3 作为“数值估计”是无偏的，但把它直接当损失求导，得到的梯度一般并不是 KL 的正确梯度（见参考文献中 2025 年关于 KL 梯度估计陷阱的论文）。

智能体场景为什么常用很小或为 0 的 β：奖励大多来自环境状态检查、单元测试这类规则验证；长轨迹训练本来就会让策略明显偏离初始模型；去掉参考模型还能省显存。保留一个小 β 的理由是实践上的：奖励里有 LLM 评审或学到的奖励模型时（第 04 课），或者观察到格式漂移、语言混杂时，KL 可以起约束作用。这两条是经验建议，不是某篇论文的结论。

8. 离策略与异步修正

为了提高 GPU 利用率，异步系统会用落后几个版本的权重继续采样（第 07 课）。这时 πold 和 πθ 差得更远，ρ 偏离 1 更多。一个简化的例子：假设每个版本都让某个 token 的 log 概率同向增加 δ，落后 k 个版本后 ρ = ek·δ。

δ = 0.05 时，k = 4 就有 ρ = 1.22，超过 1.2，A > 0 的这个 token 在 ε = 0.2 下已经没有梯度。落后越多，被 clip 掉的 token 越多，有效样本越少。常见做法是限制最大落后版本数。

训推不一致是另一层偏差（第 05 课第 3 节）：即使权重完全相同，推理引擎（vLLM、SGLang）和训练引擎（FSDP、Megatron）算出的 token 概率也不同，按“同策略”写的算法其实在做离策略训练。截断重要性采样（TIS）给每个 token 乘一个修正权重：

w_t = min( π_train(o_t) / π_infer(o_t) ,  C )      # C 是截断上限，超参数

默认是 0.30 / 0.20，权重 1.5，不截断。把它们改成 0.05 / 0.01，原始权重是 5，截断到 C = 2：截断限制了单个 token 的方差，代价是引入一点偏差。其他相关做法：

  • 提高关键层精度：MiniMax-M1 发现训练和推理的 token 概率不一致会让奖励涨不上去，把 LM 输出头改成 FP32 后，两边概率的相关系数从约 0.9x 提高到约 0.99x。
  • 用序列级比率：GSPO 论文认为序列级似然对精度差异更宽容，有可能直接使用推理引擎返回的概率，省掉训练引擎重算 πold 这一步。
  • 先测再修：用第 05 课的方法，在第一个训练步记录 |log ρ|，确认偏差主要来自精度而不是重新分词或模板改写，再决定上哪种修正。

10. 怎么选

  • 用托管服务：算法已经定了（GRPO 及其调参），你能调的是 group size、学习率、最大 token 数、奖励函数。
  • 自建且任务较短：GRPO 或 Dr.GRPO 起步，加上 DAPO 的动态采样。
  • MoE 底座：优先尝试 GSPO。
  • 长程任务、回合多：考虑回合级奖励或回合级优势，配合异步 rollout。
  • 不管选哪个：先确认奖励和环境没有问题。经验上，算法差异带来的提升通常小于奖励和数据质量带来的提升。

11. 小测验

A > 0 且 ρ = 1.5、ε = 0.2 时，这个 token 的梯度如何？
正确答案 B。ρ 超过 1.2，clip 生效，min 取到被截断的那一项，对 θ 的梯度为 0。
按 GRPO 的样本级平均，组里两条错误回答优势都是 −1，一条 100 token，一条 400 token。哪条的每个 token 被罚得更重，长期会造成什么倾向？
正确答案 C。每 token 权重是 A/(G·|oi|)，长度是 4 倍，惩罚就只有 1/4。这就是 Dr.GRPO 指出的长度偏差。DAPO 的 token 级平均和 Dr.GRPO 的常数归一化让两条回答每个 token 的权重相同。
8 条回答里 7 条正确。GRPO 除以组内 std 时，那条错误回答的优势约为多少？Dr.GRPO 不除 std 时呢？
正确答案 A。组均值 0.875，总体 std = √(0.875 × 0.125) ≈ 0.331，(0 − 0.875)/0.331 ≈ −2.65。不除 std 就是 −0.875。std 越小的组（太简单或太难）被放大得越多，这就是题目难度偏差。
A > 0，某个 token 的 ρ = 1.6，εhigh = 0.28。token 级 clip（PPO/DAPO）和 CISPO 分别怎么处理它的梯度？
正确答案 B。PPO 的 min 取到截断项后对 θ 是常数；CISPO 把截断后的权重当常数乘在 A·log π 上，梯度方向仍然存在，只是大小受限。
