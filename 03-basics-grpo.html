GRPO 入门：组内比较怎样产生学习信号

目标：不用公式也能讲清楚 GRPO 在做什么，并理解“为什么有些训练数据完全没用”。本课先手算一组优势，再看优势怎样变成每个 token 的权重、怎样改变模型的概率；然后算出“全对或全错的组”在什么情况下有多常见，以及组大小 G 该怎么选。clip、KL 和各种变体留给第 06 课。

1. 核心思想

对同一个任务采样 G 条轨迹（一组），每条得到奖励 ri。把组内平均奖励当作“及格线”：

A_i = (r_i − 组内平均) / 组内标准差

Ai 叫优势。A 为正，就提高这条轨迹里模型生成的 token 的概率；A 为负就降低。它不需要单独训练一个“价值网络”来估计及格线（PPO 需要），省显存、实现简单，因此成为 Agentic RL 的默认算法。Amazon Bedrock RFT 和 SageMaker AI 多轮 RL 底层用的都是 GRPO。

2. 一步一步算一组优势

符号：G 是组里的轨迹数，i 是第几条（1 到 G），ri 是第 i 条的奖励。组均值 mean = (r1 + … + rG) / G；组标准差 std = √( Σ(ri − mean)² / G )，它衡量组内奖励差别有多大。下面 4 条轨迹，奖励可以改；默认是一条全对（1）、一条对了一半（0.5，部分分）、两条失败（0）。

默认情况：均值 0.375，标准差 0.415。得 0.5 分的那条虽然没全对，但高于组均值，优势是 +0.30，它的 token 概率也会被提高，只是幅度小。两条失败的各是 −0.90。四个优势加起来是 0：一组里有升就有降。

这里用总体标准差（除以 G），与第 06 课一致；有的实现除以 G − 1。标准差为 0 时分母是 0，实现里会加一个很小的数（下面的拖动组件加的是 10−6），这时优势全为 0。

2.1 优势怎样变成每个 token 的权重

一条轨迹里模型生成了 |oi| 个 token（只数 loss mask 为 1 的，工具返回不算）。GRPO 原始写法里，这条轨迹的每一个生成 token 都拿同一个优势 Ai，损失先在轨迹内对 token 求平均，再对 G 条轨迹求平均：

L = −(1/G) · Σ_i (1/|o_i|) · Σ_t A_i · log π_θ(o_i,t | 上文)
每个 token 的权重 = A_i / (G · |o_i|)

上表最后一列就是这个权重（假设 4 条轨迹的生成长度分别是表里的 |oi|，可改）。注意同样的优势下，越短的轨迹每个 token 权重越大。这正是 Dr.GRPO 指出的长度偏差：长的错误回答每个 token 被罚得更轻。DAPO 和 Dr.GRPO 改了这个归一化，见第 06 课第 4 节。上面的式子省略了重要性比率和 clip（第 06 课第 1、3 节），在“刚采样完、还没更新”时它们不起作用。

建议依次点这几个预设，观察：
  1. 只有 1 条成功：那条轨迹的优势很大，模型会被强烈推向它。RL 能从稀少的成功中学习，靠的就是这个。
  2. 全部成功 / 全部失败：所有优势都是 0，这一组数据没有任何梯度，白白消耗算力。任务太简单或太难都会这样。Bedrock RFT 文档的建议是：基线奖励一直为 0 时先做 SFT，高于 95% 时可能不需要 RFT。第 4 节算这种组有多常见。
  3. 切换到 Dr.GRPO：除以标准差会放大“几乎全对”的组里的微小差异。Dr.GRPO 认为这带来了难度偏差，因此去掉了这一步。

4. 全对、全错的组有多常见

假设奖励只有 0 和 1，某个任务上模型每次成功的概率是 p，G 次采样互相独立。那么：

P(G 条全失败) = (1 − p)^G
P(G 条全成功) = p^G
P(这一组没有信号) = (1 − p)^G + p^G

例如 p = 0.1、G = 8：0.98 ≈ 0.430，0.18 小到可以忽略，约 43% 的组白跑。拖动下面的滑块，看这个比例怎样随 p 和 G 变化。

这个公式是乐观估计。它假设每个任务的成功率都是同一个 p。真实任务池里难度不一：有些题模型几乎总能做对（p 接近 1），有些几乎总做不对（p 接近 0），这些题的组几乎每次都没有信号，实际白跑的比例通常更高。第 11 课第 5.1 节的模拟器可以加入题与题之间的难度差异。对策：筛掉太简单和太难的任务，或者像 DAPO 那样丢掉这种组再补采（动态采样），或者用部分分让奖励不只有 0 和 1。

5. 优势怎样改变模型的概率

用一个最小的例子看一次更新到底做了什么。假设某道题只有三种可能的回答：甲、乙、丙。模型给每种回答一个分数 z（logit），概率是 softmax：πk = exp(zk) / Σj exp(zj)。这里把一整条回答当作一个动作，并且直接把 z 当作参数，这是为了能手算的简化；真实模型里每个 token 都有自己的 softmax，参数是网络权重。

更新规则（策略梯度）：目标是让 (1/G) Σi Ai · log π(第 i 条回答) 变大。对 softmax 求导，log πi 对 zj 的导数是 1[i = j] − πj（1[i = j] 在 i 等于 j 时为 1，否则为 0）。假设这一组 G = 3 条恰好甲、乙、丙各采到一次，梯度上升一步（学习率 η）就是：

z_j ← z_j + η · (1/G) · Σ_i A_i · (1[i = j] − π_j)
    = z_j + η · (A_j − π_j · Σ_i A_i) / G
    = z_j + η · A_j / G          # GRPO 的优势之和为 0，第二项消失

默认：甲答对（r = 1），乙、丙答错。优势 A = (+1.41, −0.71, −0.71)，η = 1、G = 3 时 z 变成 (+0.47, −0.24, −0.24)，甲的概率从 33.3% 升到 50.3%。切到“甲很少被选中”：z 的变化量完全一样，但甲的概率只从 6.3% 升到 12.1%。在真实采样里，概率 6.3% 的回答 8 次采样里一次都没出现的概率是 (1 − 0.063)8 ≈ 59%，没被采到就拿不到任何奖励，这就是第 4 节“全失败的组”的来源，也是 RL 被认为主要在放大基座已有能力的原因之一（第 01b 课第 5 节）。

把奖励改成 (1, 1, 0)：甲和乙的优势都是 +0.71，丙是 −1.41，两个正确答案一起被提高。把三个奖励设成相同：优势全为 0，点“再更新一步”概率不变。

6. 为什么要“一组”，组该多大

单独一条轨迹得了 0.6 分，你不知道它算好还是算坏：任务可能很简单（大家都 0.9），也可能很难（大家都 0.1）。同一任务的多条轨迹放在一起比较，就自动消除了任务难度的影响。代价是每个任务要跑 G 次，成本乘以 G。

G 怎么选：每步能跑的轨迹总数 N = B × G 通常由算力定死。G 大，每组更不容易全对全错，组均值这条“及格线”也更准（二值奖励下组均值的标准差是 √(p(1−p)/G)）；但 B 变小，每步见到的不同任务变少。下表固定 N，比较不同的 G：

公开的取值：DeepSeekMath 每道题采样 64 条；DeepSeek-R1 每道题 16 条、每步 32 道题；SageMaker AI 多轮 RL 默认 group_size 8；AgentCore RL Toolkit 的 τ²-Bench 实验每个任务 16 条 rollout。Wordle 博客在训练停滞后，把“比默认 8 更多的 rollout”列为下一步要试的办法之一。经验上：任务成功率接近 0 或 1 时，加大 G 比加大 B 更划算；成功率在中间时，G = 8 左右就很少出现零方差组，多出来的算力更适合换成更多不同的任务。

GRPO 完整目标里还有重要性比率、clip 和 KL 项，以及 DAPO、Dr.GRPO、GSPO 等变体各改了哪一项，见第 06 课。

7. 小测验

某任务的 8 条轨迹奖励全是 1.0，这组数据对训练有什么贡献？
正确答案 A。GRPO 只从组内差异中学习。DAPO 的“动态采样”就是把这种组丢掉，换新的任务来采样。
如果你的任务基线成功率是 0%，最合理的第一步是？
正确答案 C。全部失败时没有梯度，GRPO 学不到东西。先用示范轨迹做 SFT 或设计课程式的简单任务，让成功率进入可学习区间。
一组 4 条轨迹的奖励是 1、0.5、0、0。得 0.5 分的那条，优势是正还是负？
正确答案 B。优势只看相对组均值的高低。(0.5 − 0.375) / 0.415 ≈ +0.30。部分分让“没全对但更接近”的轨迹也能得到正信号，这是第 11 课用按字段给分的原因。
二值奖励，某类任务的成功率约 10%。G = 8 时，大约多少比例的组没有学习信号？G 提到 16 呢？
正确答案 A。(1 − 0.1)8 + 0.18 ≈ 0.430；(1 − 0.1)16 + 0.116 ≈ 0.185。这是假设所有任务成功率相同时的估计，难度不一时白跑的比例通常更高。
