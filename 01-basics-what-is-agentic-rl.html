什么是 Agentic RL

目标：用 10 分钟建立直觉，知道它和 SFT、普通 RLHF 有什么不同，为什么最近两年突然变得重要。

1. 强化学习的四个基本概念

强化学习研究的是“通过试错学习做决策”。有四个基本对象：

状态 s
智能体此刻能看到的信息
动作 a
智能体做出的选择
奖励 r
环境对结果的打分
策略 π
“看到 s 时选 a 的概率”

学习目标只有一句话：调整策略，让长期累计奖励的期望最大，写成 J(θ) = Eτ∼πθ[R(τ)]，τ 是一条完整的交互轨迹。

2. 把大模型放进这个框架

RL 概念在 LLM 智能体里对应什么
状态到目前为止的全部上下文：系统提示、用户任务、之前的思考、工具调用和返回
动作模型生成的下一个 token；若干 token 组成一次“回合动作”（一段思考 + 一次工具调用）
环境转移工具被真正执行，结果拼回上下文。这一步不由模型控制，可能出错，也可能有随机性
奖励通常在任务结束时给一次（办成没有），也可以在中间回合给
策略模型参数 θ 本身。训练就是改 θ
策略梯度的直觉：让“比平均水平好”的轨迹里那些 token 的概率变大，让“比平均差”的变小。后面所有算法，都是在回答“怎么算出‘比平均好多少’（叫优势 A）”和“怎么稳定地更新参数”。

3. 动手：切换单轮和多轮

4. 为什么它现在变得重要

  1. 可验证奖励跑通了。DeepSeek-R1 证明只用“答案对不对”的规则奖励加上 GRPO，就能让模型自己学出长链推理。把“答案对不对”换成“任务办成没有”，就是 Agentic RL。
  2. 智能体的瓶颈在决策，不在知识。模型知道每个 API 怎么用，但不知道在你的业务里先查什么、什么时候停、违反政策时要拒绝。这些只能从结果反馈中学。
  3. 小模型经过 RL 能在垂直任务上追上大模型。AWS 开源的 AgentCore RL Toolkit 公开结果：Qwen3-30B-A3B 在 τ²-Bench Telecom 客服任务上从 38% 提升到 96%（SFT + RL）；Java 代码迁移任务从 43% 提升到 76%。推理更便宜，也能私有化部署。
  4. 基础设施成熟了。开源框架（verl、slime、SkyRL 等）和托管服务（SageMaker AI 多轮 RL、Bedrock RFT 等）把门槛从“自研分布式 RL 系统”降到了“写环境和奖励函数”。

5. 小测验

下面哪个任务最适合用 Agentic RL？
正确答案 C。A 有大量标准答案，SFT 更直接；B 是单轮任务，且难以自动判定好坏；C 是多步决策、无标准轨迹、结果可程序验证，正好是 Agentic RL 的适用条件。
Agentic RL 训练时，需要给模型提供“标准的正确操作轨迹”吗？
正确答案 B。轨迹由模型自己和环境交互产生，只需要能判断结果好坏。这正是它比 SFT 更适合“正确做法不唯一”的任务的原因。不过如果模型一开始完全不会，通常会先用少量示范做 SFT 冷启动（见第 05 课）。
