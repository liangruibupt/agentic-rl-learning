什么是 Agentic RL

目标：用 10 分钟建立直觉，知道它和 SFT、普通 RLHF 有什么不同，为什么最近两年突然变得重要。本课先用一个三步的小任务手算一遍“状态、动作、奖励、回报”，再把“策略就是大模型”落到具体的概率上，最后讲什么时候不该用 RL。RL 和 SFT、DPO 等后训练方法的关系见 01b，这里不重复。

1. 强化学习的四个基本概念

强化学习研究的是“通过试错学习做决策”。有四个基本对象：

状态 s
智能体此刻能看到的信息
动作 a
智能体做出的选择
奖励 r
环境对结果的打分
策略 π
“看到 s 时选 a 的概率”

学习目标只有一句话：调整策略，让长期累计奖励的期望最大，写成 J(θ) = Eτ∼πθ[R(τ)]，τ 是一条完整的交互轨迹。

逐个解释这个式子里的符号：

  • t：第几步，从 1 开始数。st、at、rt 分别是第 t 步的状态、动作和这一步拿到的奖励。
  • 轨迹 τ：一次完整尝试的记录，τ = (s1, a1, r1, s2, a2, r2, …)。
  • 回报 R(τ)：这条轨迹上所有奖励的和，R = r1 + r2 + … + rT。有的教材会给后面的奖励乘一个折扣 γ（0 到 1 之间），LLM 任务里通常取 γ = 1，本课也是。
  • θ：策略的参数。对大模型来说就是模型的全部权重（或 LoRA 适配器的权重）。πθ 表示“参数为 θ 的策略”。
  • Eτ∼πθ[…]：期望，即“按这个策略反复做很多次，R 的平均值”。策略有随机性，同一个任务每次走的路可能不同，所以优化的是平均值。

2. 手算一个小例子：三步换货任务

把客服任务缩成三步，每一步只有两三个选项。用户说：“订单 88 的鞋请换成 42 码。”这是一个最小的马尔可夫决策过程（MDP）：每一步看到当前状态，选一个动作，环境给出新状态和奖励。

步骤 t状态 st（智能体看到的）可选动作 at
1用户请求调用 get_order(88) 查订单 / 不查，直接往下走
2用户请求 + 第 1 步的结果查退换政策 / 跳过
3以上全部调用 exchange 执行换货 / 拒绝用户 / 转人工

奖励规则（验证器）：只在最后一步给分。数据库里订单 88 确实换成了 42 码，r3 = 1，否则 r3 = 0；第 1、2 步的奖励都是 0。换货接口需要商品 ID，只有查过订单才拿得到，所以不查订单直接换货会报错。这种“只看最终结果”的奖励叫结果奖励（outcome reward）。

一共 2 × 2 × 3 = 12 条可能的轨迹。下表列出全部，当前选中的那条高亮。

结果奖励带来的问题：信用分配。看两条 R = 1 的轨迹：“查订单 → 查政策 → 换货”和“查订单 → 跳过 → 换货”。最终分数一样，单看一条轨迹，你分不出三步里哪一步是关键。GRPO 这类方法会把同一个优势值 A 分给轨迹里的每一个 token（第 03 课），好步骤和无用步骤被一起奖励。

怎么分出来：靠大量样本求平均。假设策略每一步都随机选（每个选项概率相同），把 12 条轨迹按“某一步选了什么”分组，算平均回报，就能看出哪些决定真正影响结果：

读这张表：第 1 步选“查订单”的平均回报是 1/3，选“不查”是 0，差别很大，说明这一步重要；第 2 步两种选择的平均回报都是 1/6，说明在这个验证器下“查政策”对结果没有影响。这正是 RL 做信用分配的方式：不靠人告诉它哪步关键，而是在很多条轨迹的统计里看出来。代价是需要很多样本。这里只有 12 条可能的轨迹；真实 LLM 的“动作”是一个个 token，词表有数万到十几万个 token（例如 Llama 3 是 128K），可能的轨迹数没法枚举，只能采样。回合级奖励等更细的信用分配方法见第 05 课第 2 节。
验证器只奖励它检查的东西。这个例子里“查政策”没有分，是因为验证器不检查它。如果业务上必须先核实政策，就要把它写进验证器或奖励，否则模型会学会跳过。这是第 04 课奖励设计的内容。

3. 把大模型放进这个框架

RL 概念在 LLM 智能体里对应什么
状态到目前为止的全部上下文：系统提示、用户任务、之前的思考、工具调用和返回
动作模型生成的下一个 token；若干 token 组成一次“回合动作”（一段思考 + 一次工具调用）
环境转移工具被真正执行，结果拼回上下文。这一步不由模型控制，可能出错，也可能有随机性
奖励通常在任务结束时给一次（办成没有），也可以在中间回合给
策略模型参数 θ 本身。训练就是改 θ
策略梯度的直觉：让“比平均水平好”的轨迹里那些 token 的概率变大，让“比平均差”的变小。后面所有算法，都是在回答“怎么算出‘比平均好多少’（叫优势 A）”和“怎么稳定地更新参数”。

3.1 “策略就是大模型”具体指什么

大模型每生成一个 token，先对词表里每个候选 token k 算一个分数 zk（叫 logit），再用 softmax 把分数变成概率，然后按概率抽一个出来。带温度 T 的 softmax 是：

p_k = exp(z_k / T) / Σ_j exp(z_j / T)

这个 p 就是策略 πθ(a | s)：状态 s 是到目前为止的上下文，动作 a 是下一个 token。训练改的是 θ，θ 变了，同样上下文下的 logit z 就变了，概率随之改变。T 不是参数，是采样时的设置：T 小，概率集中到分数最高的 token；T 大，概率更平均。

为什么采样多样性对 RL 很重要：RL 只能从“同一个任务的不同尝试之间的差别”里学习（第 03 课）。T = 1 时，8 次采样全部抽到同一个词的概率是 Σ pk8，约 1.9%；把 T 拖到 0.1，这个概率接近 100%，8 条轨迹一模一样，奖励也一样，这一组就没有学习信号。DeepSeek-R1 论文训练时的采样温度是 1。反过来，T 太大会采出大量胡言乱语，成功率太低同样学不动。上线时用的温度往往更低，所以评测要按上线设置做（第 02 课第 4 节）。

这里只看了一个 token。一条轨迹有成百上千个 token，每个位置的小差别会累积，所以整条轨迹的多样性比单个 token 大得多。

5. 为什么它现在变得重要

  1. 可验证奖励跑通了。DeepSeek-R1 证明只用“答案对不对”的规则奖励加上 GRPO，就能让模型自己学出长链推理。把“答案对不对”换成“任务办成没有”，就是 Agentic RL。
  2. 智能体的瓶颈在决策，不在知识。模型知道每个 API 怎么用，但不知道在你的业务里先查什么、什么时候停、违反政策时要拒绝。这些只能从结果反馈中学。
  3. 小模型经过 RL 能在垂直任务上追上大模型。AWS 开源的 AgentCore RL Toolkit 公开结果：Qwen3-30B-A3B 在 τ²-Bench Telecom 客服任务上从 38% 提升到 96%（SFT + RL）；Java 代码迁移任务从 43% 提升到 76%。推理更便宜，也能私有化部署。
  4. 基础设施成熟了。开源框架（verl、slime、SkyRL 等）和托管服务（SageMaker AI 多轮 RL、Bedrock RFT 等）把门槛从“自研分布式 RL 系统”降到了“写环境和奖励函数”。

8. 小测验

下面哪个任务最适合用 Agentic RL？
正确答案 C。A 有大量标准答案，SFT 更直接；B 是单轮任务，且难以自动判定好坏；C 是多步决策、无标准轨迹、结果可程序验证，正好是 Agentic RL 的适用条件。
Agentic RL 训练时，需要给模型提供“标准的正确操作轨迹”吗？
正确答案 B。轨迹由模型自己和环境交互产生，只需要能判断结果好坏。这正是它比 SFT 更适合“正确做法不唯一”的任务的原因。不过如果模型一开始完全不会，通常会先用少量示范做 SFT 冷启动（见第 05 课）。
在第 2 节的三步换货例子里，“查订单 → 跳过政策 → 换货”和“查订单 → 查政策 → 换货”的回报分别是多少？这说明什么？
正确答案 B。两条都把订单换成了 42 码，R 都是 1。1/3、1/6 是随机策略下“按某一步的选择分组”的平均回报，不是单条轨迹的回报。如果业务要求必须查政策，要把它写进验证器。
把采样温度 T 调到接近 0，对 GRPO 训练有什么影响？
正确答案 A。T 接近 0 时 softmax 几乎把全部概率给分数最高的 token，采样退化成贪心解码。RL 需要多样的尝试才能比较好坏，所以训练采样通常用 T = 1（DeepSeek-R1 论文就是 1）。
