RL 和后训练的关系

目标：分清“后训练”和“强化学习”这两个常被混用的词。后训练是一个阶段，RL 是一种学习方式，两者不在同一个维度上。学完能用一段话给客户讲清楚，并知道 Agentic RL 在整条流水线里的位置。

一句话结论：预训练之后、用来塑造模型行为的所有训练，统称后训练。RL 是让模型自己生成输出、按奖励信号更新的那一类方法，和 SFT、DPO、蒸馏等并列；它也是近两年推理模型和 Agent 模型能力提升的主要来源之一。反过来，后训练不等于 RL：Llama 3 的主流程就基本没有用在线 RL。

2. 核心区别：从自己的样本学，还是从固定数据学

RL 的训练循环是：当前模型（policy）对一个 prompt 生成一个或多个回答（rollout），奖励模型或验证器打分，按分数提高高分回答的概率、降低低分回答的概率（PPO、GRPO 都是这个思路），再用更新后的模型继续生成。关键在于训练数据是模型自己当下生成的。SFT 和 DPO 则用事先准备好的固定数据。

切换下面的方法，比较数据从哪来、是否在线、奖励从哪来。

为什么 DPO 常被称为 “RL-free”，但又和 RLHF 有关

DPO 论文（Rafailov et al., 2023）从 RLHF 的目标函数出发：最大化奖励，同时用 KL 约束不偏离参考模型太远。作者推导出这个目标的最优解可以写成闭式，于是把“先训练奖励模型、再跑 PPO”换成了一个直接在偏好对上算的损失。论文标题 “Your Language Model is Secretly a Reward Model” 就是这个意思。

  • 目标上，DPO 和 RLHF 优化的是同一个东西。
  • 过程上，DPO 没有采样、没有奖励模型、没有探索，就是监督学习式的训练。这是它被叫作 “RL-free” 的原因。
  • DPO 的局限也来自这里：模型只能在已有数据覆盖的回答之间调整偏好，学不到数据里没有的新行为。

3. 在线 / 离线，同策略 / 异策略

Online（在线）：训练过程中持续生成新样本并打分。Offline（离线）：训练前数据已固定。On-policy（同策略）：用于更新的样本来自当前模型。Off-policy（异策略）：样本来自别的模型或旧版本模型。这两组概念不完全等价，中间有灰色地带。点击格子看例子，虚线框是灰色地带。

4. 公开模型的后训练流水线

通用顺序大致是：SFT（冷启动 / 格式）→ 偏好优化或 RL → 拒绝采样 + SFT 或蒸馏 → 再一轮 RL，后面几步可能循环多轮；安全对齐有的放最后单独做，更多是混在 SFT 数据和 RL 奖励里贯穿全程。选择一个模型，看它实际用了哪些步骤（均已核对原论文）。

为什么是这个顺序：

  • SFT 放在 RL 前面：基座模型不会按指令回答，也不会输出固定格式。RL 如果一开始几乎拿不到正奖励，就学不动。SFT 先把输出格式和基本行为稳定下来。“SFT Memorizes, RL Generalizes” 论文也发现，SFT 稳定输出格式后，后续 RL 才能拿到收益。
  • RL 之后常接拒绝采样 + SFT：RL 产出的模型在某个领域强了，但可能牺牲了其他能力或可读性。用它采样、筛选好答案，和其他领域数据混合后重新 SFT，可以把收益固化下来并扩展到通用场景。

从这些案例能看出两个趋势：2022–2024 年，RL 在后训练中主要用于“对齐偏好”（RLHF），而且有团队（Llama 3）用 DPO 替代了它；2024 年底以后，RLVR 成为推理能力的主要来源，RL 的分量明显变重，Qwen3 的 General RL 已经包含真实环境里的多轮工具调用。

5. RL 相比 SFT 多给了什么

可以超出示范数据
SFT 的上限大致是训练数据的质量。RL 让模型自己尝试，某次尝试拿到高分就会被强化。R1-Zero 在没有任何人工推理示范的情况下，出现了自我检查、反思、长 CoT 等行为。
可以优化不可微、序列级的目标
“代码能否通过测试”“最终答案对不对”“整个任务是否完成”都无法直接对 token 求梯度。SFT 的损失是逐 token 的交叉熵；RL 只需要一个对整条输出打的分数。
没有标准答案轨迹也能学
很多 Agent 任务没有唯一正确的操作序列，只能判断最终成没成功。SFT 需要标注轨迹，RL 只需要结果。SageMaker 多轮 RL 博客用的就是这个理由。

开放问题：RL 能不能带来基座没有的新能力

泛化可能更好，但目前没有定论。两篇常被引用的论文结论方向不同：

支持 RL 泛化更好
Chu et al.，arXiv 2501.17161（“SFT Memorizes, RL Generalizes”）
在卡牌算术游戏 GeneralPoints 和导航环境 V-IRL 上比较，发现基于结果奖励的 RL 对未见过的规则和视觉变体泛化更好，SFT 倾向于记住训练数据。
注意：这是在特定合成任务上的结论；同一篇论文也强调 SFT 对 RL 是必要的。
认为 RLVR 主要是“锐化”
Yue et al.，arXiv 2504.13837（NeurIPS 2025 Oral）
用大 k 的 pass@k 测试发现：RLVR 模型在 k=1 时胜过基座，但 k 很大时基座反而更高。解释是 RLVR 主要把基座已有的正确路径变得更容易采样到，没有引出全新的推理模式；蒸馏则能从老师那里引入新模式。
注意：作者也指出，持续扩大 RL 规模、多轮 Agent-环境交互可能改变这个结论。

两篇论文测的东西不一样：一个看分布外泛化，一个看能力边界（覆盖率）。向客户介绍时，“RL 能否在基座能力之外创造新能力”应作为争论中的问题，不要当成已知结论。

6. 成本和风险，以及 Agentic RL 的位置

风险说明
奖励投机（reward hacking）模型学会钻奖励的空子，而不是真正完成任务。例如奖励模型偏爱长回答，模型就变得啰嗦。DeepSeek-R1 论文说没用过程奖励模型（PRM），一个原因就是引入基于模型的奖励必然带来 reward hacking。规则验证器也可能被钻空子（如只检查格式、测试覆盖不全）。第 04 课复现了一个真实案例
训练不稳定PPO 超参敏感，容易崩溃或熵塌缩（输出多样性消失）。Llama 3 因此没用 PPO；Qwen3 专门控制熵来保持稳定
计算成本高每一步都要生成多个 rollout，推理开销往往大于梯度更新。Agent 场景还要跑真实环境（代码执行、API 调用），更慢。R1 论文提到软件工程任务评估时间太长，没有在这类任务上大规模做 RL
能力回退（alignment tax）对某个目标优化后，其他能力下降。Qwen3 报告显示：思考模式融合和 General RL 两个阶段之后，AIME'24 和 LiveCodeBench 分数略有下降，团队选择接受这个代价换取通用性
需要验证器和环境RLVR 只适用于结果可自动判断的任务。开放式任务要依赖奖励模型或 LLM 评审，又回到 reward hacking 风险。搭建可靠的环境和评分函数往往是 RL 项目中最费工的部分
小模型收益有限DeepSeek-R1 和 Qwen3 都报告：对小模型，从大模型蒸馏比直接 RL 更划算

Agentic RL：RLVR 从单轮扩展到多轮工具环境

单轮 RLVR / RFTAgentic（多轮）RL
一次 rolloutprompt → 一个完整回答prompt → 思考 → 调工具 → 看环境返回 → 再思考 → …… → 结束
奖励对最终回答打分通常对整条轨迹的结果打分（任务是否完成），也可以加中间步骤奖励
难点验证器设计信用分配（第 3 步的决定如何对应最终结果）、环境搭建与并发、长轨迹的成本

和课程其他内容的对应关系：

  • SFT：给 Agent 冷启动，让它学会工具调用格式（见 第 05 课）。
  • GRPO：一个 prompt 采样一组 rollout，用组内相对分数算优势，不需要价值模型（见 第 03 课）。Bedrock RFT、SageMaker AI 多轮 RL、Qwen3、DeepSeek-R1 都用它。
  • RFT：在 AWS 语境里指“用奖励函数做强化微调”，即托管版的 RLVR / RLAIF。
  • RLHF：Agentic RL 的奖励也可以来自奖励模型或 LLM 评审，原理与 RLHF 相同。
Amazon Bedrock RFT（单次回答打分）
每个 prompt 生成多个回答，由 Lambda 或模型评审打分，用 GRPO 训练；支持 Nova 2 Lite、gpt-oss-20B、Qwen3 32B。文档描述的训练循环是对单个回答打分，没有描述与外部环境的多轮交互。文档的适用场景里提到了 multi-turn problem solving，具体支持到什么程度本课没有核实。

2026 年 6 月发布。Agent 部署在 AgentCore 或自建基础设施上，训练任务每次 rollout 调用 Agent，Agent 多轮调用正在训练的模型并在回合结束时返回一个奖励，用 GRPO 更新 LoRA。官方 Wordle 示例中，gpt-oss-20b 解题率在默认推理强度下从 61% 升到 84%，训练 token 费用约 339 美元。

可以直接讲给客户的一段话
后训练是指预训练完成之后、让模型“会用、好用、安全”的所有训练步骤，强化学习（RL）是其中的一类方法。SFT 和 DPO 这类方法让模型模仿或比较一批固定数据；RL 则让模型自己作答，再按奖励打分并更新，所以它能学到训练数据里没有的解法，也能直接优化“代码是否跑通”“任务是否完成”这类无法逐字标注的目标。过去几年的公开做法通常是先用 SFT 打底，再用偏好优化或 RL 提升，最后用拒绝采样或蒸馏把成果固化；DeepSeek-R1、Qwen3 这类推理模型的主要提升来自基于可验证奖励的 RL。RL 的代价是需要可靠的评分函数和环境、计算量更大、可能出现模型钻奖励空子的情况，而且学界对“RL 能否带来基座模型没有的新能力”还有争论。对企业来说，如果任务的结果能自动判断对错，可以考虑 Bedrock 的强化微调（单次回答打分）或 SageMaker AI 的多轮 RL（Agent 多步任务）；如果只是让模型学会某种格式或风格，SFT 往往更便宜也更稳。

8. 小测验

DPO 训练时会不会让模型实时生成回答再打分？
正确答案 B。DPO 的目标和 RLHF 相同，但把“训练奖励模型 + PPO”换成了闭式推导出的偏好损失，训练过程里没有采样和探索，所以常被叫作 “RL-free”。迭代式 DPO 会在每轮之间用最新模型重新生成数据，但每一轮内部仍是离线的。
Llama 3 的后训练主流程是什么？
正确答案 C。Llama 3 明确选择了 SFT + 拒绝采样 + DPO，而不是 PPO，理由是 PPO 不稳定、难扩展，DPO 计算更少。这说明后训练不等于 RL。B 是 DeepSeek-R1-Zero 的做法。
客户只想让模型按公司模板输出固定格式的报告，有大量现成的示范报告。最合适的起点是？
正确答案 A。目标是格式和风格，又有现成示范，SFT 往往更便宜也更稳。RL 的优势在于没有标准答案、但结果能自动判断的任务。
Yue et al.（2504.13837）用大 k 的 pass@k 比较 RLVR 模型和基座，发现了什么？
正确答案 B。这和 Chu et al.（2501.17161）发现 RL 分布外泛化更好并不直接矛盾：一个测能力边界（覆盖率），一个测分布外泛化。作者也说扩大 RL 规模、多轮交互可能改变结论，所以这仍是开放问题。
