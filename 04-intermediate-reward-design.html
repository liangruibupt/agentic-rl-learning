中级班 · 04

奖励设计：模型会优化你写的分数，而不是你心里想的目标

目标：能写出第一版奖励函数，并用单调性检查发现奖励作弊。

1. 奖励的三种来源

规则 / 程序验证

数据库最终状态、单元测试、编译通过、字段精确匹配。

首选：便宜、确定、难作弊。

LLM 评审

语气、完整性、政策遵循等主观项，用 rubric 让模型打分。

贵、有噪声、可能被“讨好”，权重要小，并抽样人工复核。

过程塑形

工具调用是否合法、步数、重复调用惩罚。

只用来区分同一结果档位内的轨迹，不能决定档位。

2. 动手：复现一个真实的奖励倒挂

案例来自 AWS 博客《Multi-Turn Reinforcement Learning on Amazon SageMaker AI》中的 Wordle 智能体。第一版奖励把每一步猜词的得分累加，结果出现了两个倒挂：输了还拿正分，第 1 步猜中比第 3 步猜中分还低。作者是读轨迹时才发现的。修正方法是“结果项主导 + 有界塑形项”。调参数看看排序会不会被破坏。

在版本 2 里把“成功时塑形权重”拉到 0.15 以上试试。博客作者第一次修正就用了 0.15，结果第 3 步猜中（塑形满分）反超了第 2 步猜中（塑形最低分）。相邻步数的结果分只差 0.1，所以塑形权重必须足够小，才不会跨档。

3. 展开讲：结果项主导 + 有界塑形项

reward = outcome + w × clip(shaping, −1, 1)
  • 结果项 outcome：只看任务最终办成没有，把轨迹分成几个档位。它决定排序。
  • 塑形项 shaping：只在同一档位内区分轨迹，例如“输了，但每步都在用已知线索”和“输了，而且乱猜”。
  • 有界：塑形项先截断到 [−1, 1]，再乘一个小权重 w。总分最多上下浮动 w，跨不出所在档位。

3.1 为什么两部分都需要

只用结果项：奖励太稀疏

训练初期一组 8 条轨迹常常全部失败，奖励完全一样，GRPO 的优势全是 0（第 03 课），学不到东西。塑形项让“失败得好一点”的轨迹分略高，组内就有了差异。

塑形项不设上限：被模型钻空子

本页实验台的版本 1 就是这样：每猜一步加分，整局累加。输掉的一局能拿正分，第 1 步猜中反而不如第 3 步猜中。根本原因是塑形项随步数增长，大到盖过了结果项。

3.2 “有界”到底限制了什么

clip 之后塑形项在 [−1, 1]，乘以 w 后总分浮动范围是 [−w, +w]，从最低到最高共差 2w。规则只有一条：

2w < 相邻两个档位之间的最小差距

第一步，算档位差。Wordle 修正版里，第 n 步猜中的结果分是 1.05 + 0.5 × (6 − n) / 5。n 每增加 1，(6 − n) 减 1，结果分就减少 0.5 ÷ 5 = 0.1：

成功档之间每档只差 0.1，所以成功时必须 2w < 0.1，即 w < 0.05。

第二步，验证权重。表里的两个 w 都来自 AWS 博客作者的真实迭代：第一次修正沿用了失败档的 0.15，发现倒挂后改成 0.04。

成功时的 w2w第 3 步猜中，塑形满分第 2 步猜中，塑形最低结果
0.150.30 > 0.11.35 + 0.15 = 1.501.45 − 0.15 = 1.30倒挂：慢的反而分高
0.040.08 < 0.11.35 + 0.04 = 1.391.45 − 0.04 = 1.41排序正确

为什么是 0.04 而不是 0.049？还有第二个约束：训练服务把奖励 ≥ 1.0 算作“成功”，最差的成功（第 6 步猜中、塑形最低）必须仍然 ≥ 1.0，即 1.05 − w ≥ 1.0，同样要求 w ≤ 0.05。取 0.04 给两个约束都留了余量，最差成功是 1.01。

3.3 为什么成功和失败可以用不同的 w

失败档（−0.5）离上下两边都很远：上面最差的成功是 1.01，下面“无合法猜测”是 −1.5。用 w = 0.15，失败分落在 [−0.65, −0.35]，仍然低于所有成功、高于“什么都没做”。训练初期绝大多数轨迹都是失败，正好在这个档位最需要塑形信号；成功档挤得很紧，只能用很小的权重。

3.4 换成自己的任务

  1. 列出结果档位并排序。第 10 课的客服任务（档位分值是课程自己设计的）：完全办成 +1.0 > 办成但违规 +0.3 > 办错 −0.5 > 执行禁止操作 −1.0 > 什么都没做 −1.5。分值的拉开程度表达你对各种失败的厌恶程度：违规写操作比“没办完”更危险，所以更低。
  2. 算每对相邻档位的差，取最小值。1.0 − 0.3 = 0.7；0.3 − (−0.5) = 0.8；−0.5 − (−1.0) = 0.5；−1.0 − (−1.5) = 0.5。最小差距是 0.5。
  3. 选 w 满足 2w < 最小差距。w < 0.25；课程取 0.1（2w = 0.2），留足余量。
  4. 塑形项只放过程信号：回合数、重复调用、非法参数、小权重的 LLM 评审分。凡是随步数累加的信号，必须先 clip。
  5. 写单调性测试：构造“上一档里最差的轨迹”和“下一档里最好的轨迹”，断言前者分更高。
和经典理论的关系：RL 里更严格的做法是基于势函数的塑形（Ng 等人，1999）：塑形奖励写成两个状态的势能差，可证明不改变最优策略。但它要求为每个状态设计势函数，在 LLM 智能体上难落地。“结果主导 + 有界塑形”是工程上的替代：不保证最优策略完全不变，但保证结果更好的轨迹总是得分更高，塑形只影响同档位内的偏好。

4. 防作弊清单

  • 写单调性测试。更好的结果必须总是更高分。把上面的检查写成奖励函数的单元测试。
  • 验证器对模型不可见。测试用例、目标状态在轨迹结束后才使用，否则模型会去读测试。
  • 永远返回一个奖励值。SageMaker AI 多轮 RL 中，rollout 报错或从未调用策略模型会让整个训练任务失败。用异常兜底返回最低分。
  • 奖励函数要快。Bedrock 文档建议秒级完成，避免分钟级计算和大量外部 API 调用。
  • 定期读轨迹。每隔若干步随机读 20–50 条，看高分轨迹是否真的“好”。
  • 警惕“逃避型”策略。例如客服智能体发现“转人工”从不违规，于是什么都转人工。要让转人工只在政策要求时才算成功。

5. 一个通用模板

reward = outcome + w * clip(shaping, -1, 1)

outcome  决定档位：完全成功 > 部分成功 > 失败 > 严重违规 > 什么都没做
shaping  只在档位内区分：步数、合法调用、（小权重）LLM 评审
w        小到不会跨档：w * 2 < 相邻档位的最小差距
GRPO 下，为什么还需要塑形项，只用 0/1 结果不行吗？
正确答案 B。GRPO 从组内差异中学习。全是失败时，塑形项还能告诉模型哪些失败“更接近成功”。但它必须足够小，不能改变档位排序。
