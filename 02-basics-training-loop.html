一次训练迭代

目标：看清楚 Agentic RL 训练的完整闭环，知道时间花在哪里。先点“下一步”逐步走一遍；再用 AWS 公开的 Wordle 实验把一步里的数字全部算出来，看训练器实际收到的一条数据长什么样；最后讲旧数据、检查点选择，以及每一步常见的故障。

1. 动手：逐步走一遍

2. 把一步的数字全部算出来

AWS 博客的 Wordle 实验（SageMaker AI 多轮 RL，gpt-oss-20b + LoRA）公开了足够多的数字，可以把一个训练步完整算一遍。先解释三类 token，这是托管多轮 RL 的计费口径，也是理解时间和成本的入口（定义来自博客）：

  • 预填充（prefill）token：策略模型读进去的输入 token。多轮任务里每一回合都要把之前的历史重新读一遍，所以会累积。
  • 生成（sample）token：策略模型生成的 token，包括推理（思考）token。
  • 训练（train）token：反向传播更新 LoRA 时处理的 token。
默认值的出处：B = 128、G = 8 是服务默认值，博客没有改；训练集 640 个词，100 步。博客报告的总量是 105,486 条 rollout、491,616,806 预填充、159,737,098 生成、643,308,554 训练 token，用时 12 小时 40 分钟（12.67 小时）。每条轨迹的 token 数是总量除以 105,486 后四舍五入。按 100 × 128 × 8 算是 102,400 条，比博客报告的少约 3%，博客没有解释这个差额。

几点读法：

  • 每个词被反复玩了很多次。640 个词、每步 128 个，5 步过完一遍（一个 epoch），100 步就是 20 遍；每遍每个词玩 8 局，一共 160 局。所以训练集表现会比留出集好，检查点要按留出集选（第 4 节）。
  • 时间：平均一步约 456 秒，约 7.6 分钟。这个总时间里哪些是采样、哪些是训练，博客没有拆开。按第 07 课第 3 节的拆法和那里的示例输入，rollout 阶段占一步的 83%，主要因为同步模式要等最慢的一条轨迹。
  • 成本：按博客写明的 us-east-1 列表价，训练 token 约 $339，AgentCore Runtime 另约 $79。换成你的任务时，用第 09 课第 6 节的成本估算器。

2.1 训练器实际收到的一条数据

轨迹跑完后，交给训练器的不是一段文字，而是几个对齐的数组。下面是一条缩短的客服轨迹，把它切成 token 后的样子。token id 和 logprob 都是示意数字，不来自真实的分词器或模型。点击上面的片段，看它对应的 token。







    

  • token_ids：采样时推理引擎实际产生和读入的 token id。必须原样保存，不能事后把文字重新分词，否则训练的 token 和采样的 token 可能对不上（第 05 课第 3 节）。
    • 

  • logprob：采样那一刻、每个生成 token 在旧策略下的对数概率 log πold。训练时用它算重要性比率 ρ = πθ / πold（第 06 课第 1 节）。非生成 token 没有采样概率，这里记为 null。
    • 

  • loss_mask：1 表示模型生成的 token，参与损失；0 表示提示词和工具返回，只做前向，不参与损失（第 05 课第 1 节）。
    • 

  • reward：验证器在轨迹结束后给的分数，整条轨迹一个数。
    • 

  • group_id：同一个任务的 G 条轨迹共用一个 id，算优势时按它分组。
    • 




3. 同策略数据和“稍微旧一点”的数据


同策略（on-policy）指用来更新的数据，正好是当前参数 θ 生成的。只要采样之后参数改过一次，剩下的数据就变成了旧策略生成的，叫离策略（off-policy）或“陈旧”（stale）。落后几个版本就叫陈旧度几。为什么会有旧数据：


    

  • 一批数据分几次更新。DeepSeek-R1 论文里，每次 rollout 生成 8,192 条输出，随机分成 16 个 mini-batch，每个只训练一遍。第 1 个 mini-batch 是同策略的；到第 16 个时，参数已经更新了 15 次。作为对照，DeepSeekMath 每次探索后只更新一次，严格同策略。
    • 

  • 异步采样。为了不让 GPU 等最慢的轨迹，异步系统让 rollout 不停地跑，一个训练批里混着不同版本权重生成的数据（第 07 课第 5 节）。SageMaker AI 多轮 RL 的 max_steps_off_policy 默认是 3（第 10 课记录的文档默认值）。
    • 













旧一点为什么通常没关系，旧太多为什么有问题：重要性比率 ρ = πθ(token) / πold(token) 修正了“数据是旧策略采的”这件事；clip 把 ρ 限制在 1 ± ε 附近，参数走得太远的 token 就不再贡献梯度。数据越旧，ρ 偏离 1 越多，被 clip 掉的 token 越多，有效样本越少。第 06 课第 8 节用 ρ = ek·δ 的简化例子算了这个效应，第 07 课第 5 节模拟了异步系统里各陈旧度的 token 比例。



4. 选哪个检查点，按什么设置评测


训练过程中每隔几步会存一个检查点（当时的参数）。最后用哪一个，取决于你怎么评。Wordle 博客的数字（全部来自博客）：




看的是什么数字说明


训练奖励（每局平均）约 15 步内升到 +0.57 后持平训练集上的表现，词会重复出现，不能用来选检查点


训练任务里的验证（留出 128 个词，temperature 0，low 推理强度）前 10 步从 2% 升到 31%，之后在 35% 到 48% 之间波动；第 90 步最高 48%，最后 37%博客说这些波动大多是噪声；训练任务的验证固定用 temperature 0


评测任务（同样 128 个词，默认推理强度，temperature 1.0）基座 61% → 训练后 84%（两次运行 80% 和 88% 的平均）这是上线时的设置。同一个适配器，训练曲线说 37%，按服务设置评测是 84%




三条做法：


    

  1. 按留出集选检查点，不按训练奖励。Bedrock RFT 文档也提醒要看过拟合：训练奖励上升、验证奖励下降。
    2. 

  2. 按上线时的设置评测：temperature、推理强度、最大回合数都和服务一致。验证曲线可以用 temperature 0 做趋势对比，但不能代表上线效果。
    3. 

  3. 先算噪声有多大，再比较检查点。验证集只有 n 道题时，解出率 p 的标准误约为 √(p(1−p)/n)。
    4. 

















这是二项分布的正态近似，题与题之间有关联、或者每题只跑一次时会低估真实波动。比较两个检查点时，最好在同一组题上每题多跑几次。



5. 时间花在哪里


以 AWS 博客公开的 Wordle 多轮 RL 实验为例：100 个训练步，一共玩了 105,486 局游戏，耗时 12 小时 40 分钟。真正的梯度更新只占其中一部分，大部分墙钟时间在和环境交互上。SWE 类任务一条轨迹可能跑几十分钟，这个比例更极端。


所以 Agentic RL 的工程重心在 rollout 侧：并发沙箱、超时与重试、异步调度。这是它和单轮 RL 在系统上的最大区别，第 07 课会展开。



6. 每一步可能出什么错


按第 1 节的 8 个步骤列出常见故障。标了“Wordle”的都是博客里实际遇到的。




步骤常见故障症状先查什么 / 去哪课


① 取任务任务太简单或太难；训练集和验证集重叠大量组全对或全错，奖励不动；验证分虚高先测基线成功率（第 09 课第 2 节）；训练和验证任务不重叠（Wordle 的 640 和 128 个词没有重叠）


② 开始采样生成上限太小；温度太低还没调用工具就被截断；组内轨迹几乎一样Wordle：默认 4096 token 时 gpt-oss 常在第一次调用工具前就用完，改成服务上限 8192；温度见第 01 课第 3.1 节


③ 多轮交互并发下鉴权失败；一条 rollout 没请求过模型；训练中重新部署智能体403；整个训练任务失败Wordle：32 个并发时凭证刷新出问题，改为单个自动刷新的会话 + 短缓存 + 遇 403 重签；任何 rollout 都要返回一个奖励；训练期间不要重新部署（第 07 课第 8 节）


④ 记录轨迹事后重新分词；mask 标错第一步训练时 |log ρ| 就很大；工具返回被训练第 05 课第 1、3 节


⑤ 计算奖励奖励倒挂：差的轨迹分更高奖励涨了，任务成功率没涨Wordle 第一版奖励里，输掉的一局能拿到约 +0.49；读轨迹，写单调性测试（第 04 课第 2 节）


⑥ 估计优势组内奖励全一样优势全 0，算力白花第 03 课第 4 节算零方差组的比例


⑦ 梯度更新学习率太高；熵塌缩Wordle：学习率太高时模型把工具调用写成普通文字，每条轨迹拿同样的最低分，梯度消失；回答越来越像降学习率；看熵和有效工具调用率（第 05 课第 6 节、第 06 课第 3 节）


⑧ 权重同步异步时数据太旧被 clip 的 token 比例上升，训练变慢或不稳限制最大陈旧度（第 07 课第 5 节、第 06 课第 8 节）




Bedrock RFT 文档还列了几种要警惕的训练曲线：奖励停在 0.15 以下不动、奖励方差随时间变大、验证表现下降。



7. 关键术语




术语含义


Rollout用当前策略完整跑一遍任务，得到一条轨迹


Group size（G）同一任务采样几条轨迹用于互相比较，常见 8–16


Global batch每个训练步取多少个任务，例如 128。每步轨迹数 = batch × G


Verifier（验证器）判定任务是否成功的程序，轨迹结束后才运行，对模型不可见


Weight sync把训练后的新权重同步到推理引擎


LoRA只训练少量低秩适配器参数，托管服务普遍采用，成本低


Epoch把训练集里的任务全部用过一遍


检查点（checkpoint）训练中某一步保存下来的参数，可以单独评测和部署


Loss mask标记哪些 token 参与损失：模型生成的为 1，提示词和工具返回为 0





8. 小测验


每步 128 个任务、group size 为 8，一个训练步要跑多少条轨迹？



正确答案 B：128 × 8 = 1,024。这就是 Agentic RL 需要大规模并发沙箱的原因。


Wordle 实验里，训练任务的验证曲线最后是 37%，按服务设置（temperature 1.0、默认推理强度）评测是 84%。上线前应该相信哪个数？





正确答案 C。评测要和服务设置一致。另外 128 道题时解出率 40% 左右的标准误约 4.3 个百分点，曲线上 35% 到 48% 的波动大多是噪声，选检查点时要把这一点算进去。


一次 rollout 生成 8,192 条输出，分成 16 个 mini-batch 依次更新、每个只训练一遍。第 16 个 mini-batch 训练时，数据落后当前参数几个版本？





正确答案 A。这是 DeepSeek-R1 论文的设置。数据是同一次采样产生的，但参数在训练途中已经变了，重要性比率和 clip 负责修正这部分偏差。


训练奖励一直在涨，但留出集的成功率不动。下面哪项最该先查？





正确答案 B。常见原因是奖励倒挂（Wordle 第一版奖励里输掉的一局也有正分）或过拟合训练任务。先确认奖励和评测是对的，再谈算法和超参（第 04、05 课）。
